## LinkedIn project description

I designed and developed Meridian to explore a practical supply-chain problem: coordinating purchasing, production, inventory, freight and client follow-ups when information is scattered across separate records.

The web application connects six operational modules, with saved demonstration workflows for purchase order approvals, shipment planning, warehouse receipt reconciliation, client update drafts and assigned actions. An illustrative air/sea freight map adds geographic context to incoming shipments.

The scenario covers eight fictional brands, 250 product variants, 20 manufacturers and four Australian warehouses over twelve months. The release was validated with 26 automated tests, TypeScript checks, a production build and browser workflow checks. The public repository includes the business case, architecture, user guide and application screenshots.

Independent portfolio demonstration using simulated data. No external orders, carrier bookings or client messages are submitted. Business benefits remain hypotheses for a future pilot; no actual client savings are claimed.

## Optional LinkedIn post

Where is the order, what happens next, and who owns the follow-up?

Those questions shaped Meridian, my e-commerce supply-chain and client-operations project. It connects purchasing, inventory, freight, receipts and client communication in a single web application, with saved demonstration workflows and an illustrative air/sea route map.

I approached the project as a business analysis exercise as well as an application build: define the operating problem, connect the records, identify exceptions and make the next action clear.

The scenario uses simulated data for eight brands and 250 product variants. The public showcase includes the business case, user guide, architecture and screenshots.
