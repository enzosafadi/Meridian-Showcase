# Repository working requirements

- Preserve the owner-approved scope and requirement provenance. Distinguish owner direction, derived engineering requirements and unconfirmed client answers.
- Save source to GitHub before deployment. Maintain this repository visibility.
- Use realistic, clearly labelled simulation data. Never invent client outcomes, approvals, tests or production readiness.
- Maintain the horizontal concept-to-SALE roadmap with a clearly visible thick vertical navy current-stage marker. Move it only with milestone evidence.
- Run `python tools/verify_repository.py --visibility public` with the declared dependencies. Record actual results and unresolved scope.
- Review disclosure before publishing source, screenshots, demos or commercial information.
- Never add `Project Documents`, confidential specifications, customer approvals or private commercial registers to this public repository. Public showcases do not certify private implementation.
